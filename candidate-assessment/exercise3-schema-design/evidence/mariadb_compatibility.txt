MariaDB compatibility check
============================
All three exercises' SQL (schema.sql / ddl.sql / reconciliation.sql /
example_queries.sql) were re-run against a real MariaDB 10.11.14 instance
(separate from the MySQL 8.0 instance used elsewhere in this assessment) to
confirm portability to the candidate's local MariaDB/XAMPP environment.

Result: 100% clean. No syntax errors on generated columns, REGEXP_REPLACE,
window functions (COUNT(*) OVER PARTITION BY), recursive CTEs (dim_date),
JSON columns, or CHECK constraints -- all supported identically by MySQL 8.0
and MariaDB 10.2+.

Exercise 1: schema + reconciliation logic -- clean run, 0 errors.
Exercise 2: schema.sql (transactions/checkpoint/runs/rejects) -- clean run, 0 errors.
Exercise 3: ddl.sql (23 tables) + seed.sql + example_queries.sql -- clean run,
0 errors, results identical to MySQL 8.0 and to the dbt mart's independently
computed figures:
  bonus_cost_pct_of_ngr = -27.78  (MySQL, MariaDB, and dbt mart all agree)

One fix made during this check: example_queries.sql query (b) originally
computed its NGR denominator as raw GGR (turnover - payouts), omitting the
bonus-cost subtraction that query (a) and the dbt mart both apply -- a real
inconsistency, caught precisely because comparing MySQL and MariaDB output
side by side surfaced the mismatch. Fixed to share the same GGR-minus-
realised-bonus-cost definition everywhere.
